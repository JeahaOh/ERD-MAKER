# 용어사전과 이름 정책

기준일: 2026-10-20. 범위는 용어사전 편집·교환과 테이블/컬럼 이름 정책이다. 원본 화면의 모든 동작·모든 과거 사전 버전과의 동등성을 의미하지 않는다.

## 화면과 파일

- 왼쪽 활동 메뉴의 책 아이콘 `용어사전 열기`로 진입한다. 모델이 없어도 사전을 편집·저장할 수 있다.
- `.xdic`은 모델과 별도의 UTF-8 XML이다. `http://exerd.com/term-model`의 TermDictionary 1.0/1.1 구조를 읽는다. 원본 메타모델 대조는 현재 3.3.56·1.1 어휘 fixture에 한정한다.
- 용어명·물리 약어·논리/물리 설명·논리/물리 동의어·태그를 추가·수정·삭제하고 검색한다. 설명은 여러 줄을 편집할 수 있다.
- 태그의 이름·설명을 편집한다. 사용 중인 태그는 연결 해제를 명시해야 삭제할 수 있으며 남은 참조 인덱스를 보정한다. 속성형과 href형 로컬 태그 참조를 처리한다.
- 해석하지 못한 태그 참조와 용어 참조가 있으면 관련 구조 삭제를 거부한다. 원본의 외부 참조를 추정해 지우지 않는다.
- 원본을 편집하지 않고 저장하면 BOM·줄바꿈을 포함한 바이트를 그대로 유지한다. 편집 시 XML 서식은 바뀔 수 있으나 미지 속성/요소·설명·CDATA·외부 참조를 보존한다.
- 가져오기는 항목 수를 먼저 보여주고 교체·병합·취소를 선택한다. 병합은 동일 이름의 다른 내용·네임스페이스·구분자 정책 충돌을 거부한다. 자동 병합할 수 없는 루트 확장 정보는 교체 또는 별도 보관을 요구한다.
- 사전에는 자체 20단계 Undo/Redo가 있고 파일 이름도 함께 복원한다. 모델의 Undo/Redo와 독립적이다. 사전 화면의 Ctrl/Command+S는 사전을 내려받는다.

## 구분자 정책과 원본 호환 경계

원본 Ecore의 `TermDelimiter`는 내부 계산 타입이다. TermDictionary.term은 Term만 수용하므로 이 타입을 용어 목록에 넣은 초기 실험은 원본 코드에서 ArrayStoreException으로 거부됐다. 실패를 성공으로 집계하지 않았다.

수정 구현은 앱 구분자 정책을 `ERD-MAKER-TERM-DELIMITERS-V1:` XML 주석의 UTF-8 JSON hex로 저장한다. 원본 어휘 목록을 바꾸지 않으며 원본 TermModelPackage/EFactory가 이 파일을 정상 수용하는 것을 확인했다. 앱은 정책을 다시 읽고 XLSX의 Delimiters 시트로 교환한다.

**원본 프로그램의 재저장은 이 앱 전용 주석 정책을 제거할 수 있다.** 어휘·동의어·태그의 보존과 앱 정책 보존을 구분하며, 화면에도 이 제한을 표시한다. 원본 재저장 뒤 정책까지 보존됐다고 보고하지 않는다.

## 이름 변환

- 사전의 용어명·동의어를 물리 약어로 변환하고, 물리 약어·물리 동의어로 역방향 조회한다.
- 정확히 일치하는 복합 용어를 우선 사용한다. 조합 이름은 사전 색인과 메모이제이션(이미 계산한 부분 결과 재사용)으로 해석한다. 미등록 단어·여러 분해 결과는 검토 대상으로 반환한다.
- 대소문자·조합 구분자·테이블/컬럼 접두사·최대 길이를 지정한다. 새 물리명은 영문자/밑줄로 시작하는 영문·숫자·밑줄로 제한한다.
- 전체 모델 또는 테이블 범위에서 미리보기 후 대상 행을 선택한다. 같은 스키마의 테이블명, 같은 테이블의 컬럼명 충돌을 검사한다.
- `applyNamingPolicy` 명령은 미리보기 당시의 물리명·논리명을 다시 확인하고 전체를 한 트랜잭션으로 반영한다. 충돌·잘못된 이름·CHECK 참조·관련 SQL 정의가 있으면 전부 거부한다. SQL 본문을 자동 치환하지 않는다.
- UUID·키/관계 참조를 유지하고 물리명만 명시값으로 바꾼다. 모델 실행 취소 한 번으로 일괄 변경을 되돌린다.
- 모델에서 논리/물리 이름 쌍을 사전으로 역추출할 수 있다. 같은 논리명에 물리명이 다르면 임의 선택하지 않고 충돌로 보고한다.

## 모델 연결과 복구

- 모델의 기존 `Configuration.termFilePath`를 표시하며 파일을 찾지 못해도 유지한다. 사전 열기·새 사전 만들기는 이 경로를 바꾸지 않는다.
- `현재 사전 경로 연결`과 `모델 사전 연결 해제`만 모델의 경로를 변경한다. 브라우저가 임의의 로컬 경로를 자동으로 읽지 않는다.
- 사전 복구본은 이 브라우저의 별도 localStorage 키에 XML·파일명·정책을 보관한다. 모델 IndexedDB 복구와 구분한다.
- 복구 읽기/쓰기 실패를 표시한다. 저장소가 가득 차도 메모리의 사전을 파일로 다운로드할 수 있다. 강제 종료·다중 창의 사전 동시 편집 충돌은 이번 검증 범위가 아니다.

## CSV·XLSX 교환

- XLSX는 Terms(용어), Tags(태그/설명), Delimiters(앱 구분자 정책)의 3개 시트를 사용한다. 표준 inline/shared 문자열을 읽으며 출력은 수식이 아닌 문자열 셀이다.
- CSV는 용어 7개 열과 연결 태그명만 교환한다. 설명의 따옴표·쉼표·여러 줄과 배열형 동의어를 처리한다. 앱 CSV 식별 행으로 탭 보호 문자를 가역적으로 처리한다.
- CSV는 태그 설명·구분자·미지 XML 확장 정보를 모두 표현하지 못한다. `.xdic`을 원본 보관 형식으로 사용한다. 이 자체 XLSX/CSV 레이아웃을 원본 eXERD Excel 마법사의 전체 형식과 동일하다고 주장하지 않는다.
- DTD/ENTITY·잘못된 UTF-8/XML·미지원 버전을 거부한다. 입력 파일 16MiB, XLSX 해제 합계 32MiB/1,000엔트리, 교환 용어 20,000행, 워크시트 256열 제한을 둔다.
- XLSX 수식·외부 워크시트·경로 탈출·중복 셀·잘못된 공유 문자열·중복 의미의 열 제목은 거부한다. 저장된 수식 결과를 실제 값으로 추정하지 않는다.

## 확인한 검사

- 단위검사: XML 문자 참조·BOM·확장 정보·태그 참조/병합·구분자 정책·양방향 이름 변환·충돌/오래된 미리보기·CHECK 거부·모델 경로 보존·XLSX/CSV·수식/잘못된 입력. 20,001개 용어 사전의 반복 복합 조회도 확인한다.
- Chrome E2E: 가져오기 검토·편집·사전 Undo/Redo·키보드 저장·3형식 다운로드·경로 연결·일괄 이름 변경과 모델 Undo/Redo·재실행 복구·저장소 실패 및 잘못된 가져오기 후 초안 보존.
- 독립 openpyxl로 앱 XLSX의 3시트·설명 줄바꿈·태그 설명·수식 없음 확인. openpyxl이 재저장하거나 새로 만든 XLSX를 앱 가져오기 코드로 다시 읽었다. 실제 Excel/LibreOffice 화면 검증과는 구분한다.
- 원본 TermModelPackage/EFactory + EMF XMLResourceImpl로 사전 어휘·참조 읽기/저장 대조. 원본 FileDocument가 사용하는 리소스 종류와 같지만 GUI 문서 제공자나 사전 편집기를 직접 실행한 것은 아니다.
