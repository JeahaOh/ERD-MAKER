# 원본 조작 실험·환경·증거 행렬

- 기준일: 2026-10-15. 제공 원본은 읽기 전용이며 실험 입력/출력은 `.analysis/acceptance/<case>/<environment>/`에 보관한다.
- 아래 표는 실행 명세다. **표가 존재하는 것과 시험 통과는 별개다.** 수행 결과가 없으면 NOT_RUN으로 남긴다.
- 원본 제품 이용 조건은 원본 환경에 적용한다. 독립 앱의 로컬 편집은 로그인·라이선스 키·활성화 서버·기간 제한 없이 제공한다. 원본의 인증/활성화를 제거하는 방식을 구현 경로로 삼지 않는다.

## 결과 기록과 판정

- 필수기록: caseID, 원본입력SHA, 원본제품버전, OS/CPU/RAM/화면, 앱빌드SHA, 실행명령, 편집대상UUID, 전후기대값, 출력SHA, 컨테이너검사, 객체diff, 원본GUI화면, 원본엔진로그, DB readback, 결과.
- 결과값: PASS / FAIL / NOT_RUN / BLOCKED. 일부 조작만 통과한 경우 실험단계를 분리하고 전체 PASS로 합치지 않는다.
- 층별 판정: 컨테이너정합 → 코덱의미 → 원본모델엔진읽기 → 원본GUI열기/편집 → 원본재저장 → DB실행 → 사용자업무수용. 서로 대체하지 않는다.
- 원본 Java 모델엔진으로 readback한 결과는 강한 코덱증거지만 **원본프로그램 GUI 재열기 완료와 같지 않다.** 전체본원본 실행환경이 확보될 때까지 해당열은 미검증이다.
- R01·A01실파일수량기준은 계획서의 609테이블·10,045컬럼·561FK·118도메인·38다이어그램·53메모다. Binary EObject수와 XML UUID수는 서로 다른 지표이므로 같은수치가 아니어도 오류로 단정하지 않는다.
- 성능수치·지원버전·DB별PASS는 결과보고서에 실제 관측값을 기록한 후에만 확정한다.
