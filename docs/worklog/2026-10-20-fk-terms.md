# FK 옵션·용어사전 구현과 검증

- 실행일: 2026-10-20 KST. 사용자 요청: 계속 테스트하고 FK 옵션과 용어사전을 구현. 이후 프로젝트 E2E 실행을 상시 허용했다.
- 기존 미추적 소스와 원본을 보존하고 작업자를 추가하지 않았다. commit/push·배포·패키지 갱신·인증 변경·원본 삭제는 수행하지 않았다.

## 구현 결과

- FK: DB별 옵션 표시·편집·원본 기본값 복귀·입력/조합 검사. 그룹/제약/대응 UUID·카디널리티·자식 PK/NULL 보존, Worker 원자적 적용·Undo/Redo·저장 재열기.
- 사전: 용어/약어/논리·물리 동의어/설명/태그 CRUD·검색·참조 검사·가져오기 검토·병합·자체 Undo/Redo·복구.
- 교환: 원본 `.xdic` XML 보존 편집, 3시트 XLSX, CSV. 여러 줄·문자 참조·BOM·미지 확장 정보 및 태그 참조 처리.
- 이름 정책: 정방향/역방향 조회·복합 이름 해석·대소문자/구분자/접두사/길이·미리보기·충돌/오래된 상태/CHECK/SQL 정의 검사·선택 일괄 적용·모델에서 사전 역추출.
- 모델 연결: 기존 termFilePath를 유지하며 명시적인 연결/해제만 반영. 사전과 모델의 저장·실행 취소·복구를 분리했다.
- 처음부터 사전 코드를 모두 내려받지 않도록 화면을 지연 로딩했다. 최종 주 화면 JS 약 491kB, 사전 화면 약 116kB이며 빌드 청크 경고를 숨기는 설정은 추가하지 않았다.

모든 npm/node 명령은 Node 24 경로를 앞에 지정했다. Chrome E2E는 사용자의 상시 허용 범위에서 필요한 실행 권한으로 수행했다.

## 발견하고 수정한 문제

- Node 24에서 새 E2E의 JSON import 속성 누락으로 테스트 로딩이 실패했다. import 속성을 명시하고 재실행해 해결했다.
- 숫자 XML 문자 참조가 설명에 문자 그대로 남았다. 속성과 텍스트를 명시적으로 복호화하여 여러 줄·엔티티의 중복 변환을 막았다.
- 원본 TermDelimiter 내부 객체를 사전의 Term 목록에 넣은 실험이 원본 모델에서 ArrayStoreException으로 거부됐다. 생성 방식을 수정했다. 비 containment 확장 속성 인라인 실험도 원본 리소스 소속 문제가 있어 채택하지 않았다.
- 앱 구분자는 원본 어휘와 분리된 주석 정책으로 저장한다. 원본 모델 수용을 확인했지만 원본 writer가 정책 주석을 제거하는 사실도 별도로 검사·표시한다.
- 원본 writer가 기본 ASC를 생략하면 MySQL/MariaDB SQL 문자열이 달랐다. 누락 시 ASC를 명시 출력하도록 수정하고 두 방언 회귀검사를 추가했다.
- 사전 교체/Undo의 파일명과 선택 상태, href형 태그 참조의 삭제/병합 인덱스, 모호한 CSV 제목·잘못된 XLSX 공유 문자열 등도 검증·보정했다.

## 증거와 재현

- `.analysis/fk-terms-20261020/evidence.json`: 현재 소스·빌드·검사·보고서·산출물 SHA-256과 범위.
- `matrix/manifest.json`: 독립 FK 옵션 모델 9개와 옵션·입력 해시.
- `matrix-oracle/report.json`: 원본 실행 결과. `app-readback.json`: 앱 역판독 결과.
- `final/`: 최종 브라우저 다운로드 4개, 원본 저장본, 원본 그래프 비교, 앱 역판독, XLSX 독립 대조.
- `test-results/fk-options.png`, `test-results/term-dictionary.png`: 실제 Chrome 화면. `.last-run.json`은 최종 통과 상태다.
- 생성: `node_modules/.bin/vite-node app/scripts/compatibility/fk-options-matrix.ts .analysis/NEW_MATRIX`.
- 원본 모델 검사: `python3 app/scripts/compatibility/original_oracle.py INPUT.exerd --describe --save NEW_OUTPUT.exerd` 및 `--xml`.
- 사전 검사: `python3 app/scripts/compatibility/original_oracle.py INPUT.xdic --term --save NEW_OUTPUT.xdic`. 이 모드는 원본 TermModelPackage/EFactory와 EMF XMLResourceImpl을 사용하며 GUI 문서 제공자를 실행한 것은 아니다.

## 남은 경계

- 새 옵션 조합의 실제 DB 서버 실행과 최신 Electron·타 OS 실행은 이번에 수행하지 않았다. 원본 GUI 호스트의 의존성 문제도 남아 있어 이번 기능의 원본 화면 수용을 주장하지 않는다.
- 원본 writer에서 어휘·동의어·태그는 보존되지만 앱 전용 구분자 주석은 제거될 수 있다. XLSX/CSV는 자체 교환 레이아웃이며 원본 Excel 마법사의 모든 형식·구버전 `.xls` 지원이 아니다.
- FK 인덱스 정책·Tibero 상태 등 SQL 생성기가 해석하지 못하는 메타정보는 파일에 보존하고 기존 DDL 진단으로 표시한다. 모든 저장 옵션의 실행 동등성이나 DB별 모든 조합을 검증했다고 확대하지 않는다.
- 사전 다중 창 충돌·강제 종료, 원본과 이름 정책의 모든 세부 규칙 일치, 전체 제품 수용은 남아 있다.
