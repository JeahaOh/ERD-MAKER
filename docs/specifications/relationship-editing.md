# 관계 속성 편집

기준일: 2026-10-20. 범위: `editRelationship`과 관계 속성 패널의 로컬 구현·검증. 원본 제품 전체의 동등성이나 전체 DB 옵션 편집 완료를 뜻하지 않는다.

## 선택과 입력

- 관계선 또는 관계 라벨을 클릭하면 속성 패널을 연다. 관계선은 접근 가능한 버튼 이름을 제공하며 Tab 이동, Enter·Space 선택, Escape 선택 해제를 지원한다.
- 자식 테이블의 FK 편집 항목에서도 `관계 속성 편집`으로 진입할 수 있다.
- 부모 키는 기존 PK(기본키) 또는 UK(고유키)에서 선택한다. 키의 각 컬럼에 서로 다른 자식 컬럼을 대응시킨다.
- 부모 키와 자식 컬럼 대응을 변경할 때 컬럼 개수·자료형·중복·소속을 검사한다. 명시적으로 빈 자료형은 도메인 상속값으로 대체하지 않는다.
- 그룹 이름과 외래키 제약 이름은 독립적으로 편집한다. 삭제·갱신 등 DB별 옵션은 [FK 물리 옵션](foreign-key-options.md) 하위 패널에서 별도 명령으로 편집한다.

## 저장 계약

- FK(외래키) 그룹과 제약 객체를 교체하지 않고 UUID(고유 식별자)·물리 옵션을 유지한다. 기존 대응 객체는 부모 컬럼 일치, 자식 컬럼 일치, 남은 객체 순으로 재사용한다.
- 대응 개수가 줄면 불필요해진 대응만 제거한다. 늘면 필요한 대응만 생성하므로 없어진 객체의 UUID까지 유지한다는 의미는 아니다.
- 식별 관계로 바꾸면 대응 자식 컬럼 중 PK에 없는 컬럼을 추가한다. 식별 해제는 기존 PK 컬럼·순서·구성 객체를 제거하지 않는다.
- PK 확장이 다른 FK를 무효화하면 전체 명령을 거부한다. 종속 FK를 자동 삭제하지 않으며 실패한 입력 문서도 바꾸지 않는다.
- 카디널리티(관계 양쪽의 허용 개수)만 바꾸면 관계 표시 속성만 수정한다. UNIQUE·NULL·FK 제약과 생성 SQL은 유지한다.
- Worker 성공 후 화면을 갱신하고 Undo/Redo 및 바이너리·XML 저장/재열기에 반영한다.
- UUID 없는 원본 `Relation`의 `binary:<id>`는 현재 그래프용 참조다. 저장 중 바뀔 수 있는 숫자 객체 ID를 영구 UUID로 취급하지 않는다.

## 확인한 검사

- `app/tests/unit/native-relationship-edit.test.ts`: 7개. 카디널리티 전용 변경의 전체 그래프 차이와 SQL 불변, 복합 대응 교환의 대응 UUID·FK 옵션 보존, 키 길이 변경, 다른 부모 테이블로 변경, 식별 해제의 PK 보존, 하위 FK 의존성 거부, 잘못된 입력의 원자성(전부 적용되거나 전부 거부됨)을 검사한다. 각 명령은 저장·재열기와 입력 불변도 확인한다.
- `app/tests/e2e/relationship-edit.spec.ts`: 실제 Chrome의 관계 그룹 클릭과 선 위 좌표 클릭, Tab·Shift+Tab·Enter·Space·Escape, 중복 대응 차단, 복합 대응 변경, Undo/Redo, 부모 고유키 전환, 식별 설정·해제, 독립 이름 변경을 검사한다.
- 브라우저가 실제 다운로드한 `.exerd`를 다시 열어 FK 그룹/제약 UUID, `useIndexing`, `onDeleteRule=CASCADE`, `deferrable`, 식별 해제 후 PK 구성 객체 UUID와 생성 SQL을 대조한다. 카디널리티만 변경한 중간 저장본은 `childCardinalityType` 한 곳만 바뀌고 SQL이 같은지 확인한다.
- 10/20 최종 전체 단위검사 21파일 225개 통과(9.46초), 전체 Chrome E2E 13개 통과(41.7초), 실패·생략 0. E2E 명령에 포함된 TypeScript/Vite 빌드도 통과했다.
- 후속 호환성 검사에서 이 브라우저 저장본을 원본 3.3.56 파일 인식기·바이너리 reader·XML reader가 모두 수용했다. 두 표현은 58객체, 원본 reader의 저장 속성 그래프 차이 0이다. 원본 writer 재저장 후 원본 reader의 그래프 차이도 0이다.
- 원본 writer 출력의 앱 역판독은 관계·대응/PK 구성 UUID·FK 옵션·SQL 동일을 확인했다. 앱의 원문 비교에는 좌표 2곳의 정수/실수 문자열 표기 차이가 남으며, 좌표 숫자가 동일한 항목만 허용했다. [호환성 실행 기록](../worklog/2026-10-20-relationship-compatibility.md).

## 남은 검증

- 이번 관계 편집 저장본을 원본 GUI에서 직접 재열기, DB별 전체 옵션 조합과 실제 서버 실행, 스크린리더·IME·여러 화면 크기는 검증하지 않았다.
- 원본 GUI 호스트는 설치된 DBeaver의 Eclipse 버전 변경으로 기존 설정의 참조가 끊어졌다. 새 격리 설정을 준비했지만 실행 시 의존성 오류가 기록되고 종료되어 이번 파일의 원본 화면 재열기는 여전히 미검증이다.
- 관계 수동 경로와 원본 표기 방식 전체는 별도 구현 범위다. FK 옵션 직접 편집은 후속 구현·검증했다.
- 기존 macOS 패키지는 이번 관계 표시·편집 변경 전 산출물이다. 이번 작업에서 패키지 생성·설치·배포는 하지 않았다.
