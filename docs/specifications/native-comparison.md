# 원본 모델 전체 비교

- 구현: `app/src/formats/exerd/compare.ts`의 `compareNativeDocuments(before, after)`.
- 입력 정본은 두 `NativeExerdDocument.graph`다. 첫 다이어그램·화면 축약 모델·객체 개수만으로 비교하지 않는다.
- **읽기 전용 비교**다. 파일 저장·DB 연결·부분 병합·원본 그래프 변경을 수행하지 않는다.

```ts
const result = compareNativeDocuments(beforeDocument, afterDocument);
// result.changes: added / removed / changed / moved
// result.summary: 객체·속성 비교 범위, 분류별 개수, 매칭 신뢰도, 처리 시간
```

| 변경 필드 | 의미 |
|---|---|
| `id` | 객체 UUID/경로·변경 종류·속성으로 만든 안정된 변경 식별자 |
| `objectType`, `uuid`, `path` | 실제 대상의 클래스·선택적 UUID·포함 경로 |
| `feature` | 달라진 속성. `$class`, `$proxy`, `$containment`는 구조 변경용 이름 |
| `before`, `after` | 비교 전후 실제 속성·참조 대상·순서. 추가/삭제는 객체 스냅샷 |
| `risk` | 추가·파괴·이름 변경·참조·순서·배치·메타데이터·검토 구분. 자동 SQL 위험 판정은 아님 |
| `match` | UUID/이름/포함 위치/참조 key/순번/proxy에 따른 매칭 전략과 신뢰도 |

요약에는 `total`, `added`, `removed`, `changed`, `moved`, 양쪽 객체 수, 매칭 객체 수, `exactMatches`, `tentativeMatches`, 미매칭 수, 비교 속성 수, `durationMs`가 있다.

## 매칭 원칙

1. **같은 UUID가 우선**이다. 같은 테이블의 물리명이 바뀌면 테이블 삭제·추가로 분해하지 않고 `physicalName` 변경으로 기록한다.
2. UUID가 다른 독립 모델은 루트 역할과 단일 포함 역할을 먼저 연결한다. 이후 같은 부모 역할 안의 스키마·테이블·컬럼 등의 이름이 양쪽에서 유일할 때 임시 매칭한다.
3. 외부 모델의 이름 매칭은 `tentative`다. DB별 대소문자 접기·명명 유사도·사용자 의도를 추측하지 않는다.
4. UUID 없는 EMap 항목은 **부모 + 포함 속성 + key**로 연결한다. key가 객체 참조면 원시 배열 번호 대신 그 대상의 매칭 정체성을 사용한다.
5. 이름 없는 반복 객체는 바뀌지 않은 내용으로 연결할 수 있다. 마지막 순번 매칭은 **양쪽 UUID가 없고 남은 항목 수가 같을 때만** 사용하며 임시 매칭으로 표시한다.
6. UUID가 다른 테이블의 이름까지 달라졌다는 이유만으로 배열 위치를 보고 rename으로 확정하지 않는다. 근거가 부족하면 삭제·추가로 남긴다.

독립 모델에서 의미 차이가 0건이어도 `tentativeMatches > 0`이면 UUID로 동일성이 입증된 결과가 아니다. UI는 이 경우 이름·역할로 대응시킨 결과라는 사실을 함께 표시해야 한다.

UUID는 매칭 근거와 `beforeUuid/afterUuid`에 보존한다. 독립 모델을 임시 매칭한 뒤 모든 UUID 차이를 다시 일반 속성 차이로 출력해 수만 개의 가짜 설계 변경을 만들지는 않는다.

## 비교 범위

- 스키마·테이블·컬럼·PK/FK·대체키·인덱스·CHECK·도메인·업무영역·다이어그램·배치·메모·물리 속성·확장 속성 등 **루트에서 도달 가능한 영속 객체 전체**를 비교한다.
- 이름·주석·자료형·기본값·NULL·순서·참조·옵션·객체 종류·외부 proxy 주소를 포함한다.
- UUID로 연결한 자식의 배열 번호가 바뀌어도 다른 객체로 만들지 않는다. 같은 멤버의 순서만 바뀌면 부모 목록의 `moved` 변경으로 기록한다.
- 객체가 다른 스키마/포함 속성으로 옮겨지면 `$containment` 이동과 양쪽 부모 목록 변경을 기록한다. 단순 삭제로 뒤 항목의 배열 번호가 당겨지는 현상을 개별 객체 이동으로 기록하지 않는다.
- `location` 변경은 배치 이동이다. 크기·테마·인쇄·표시 설정은 해당 실제 속성 차이로 남긴다.
- 참조는 양쪽에서 매칭한 객체 정체성으로 대조한다. 바이너리 내부 숫자 ID가 달라져도 같은 대상이면 참조 차이로 보고하지 않는다.
- FeatureMap은 항목의 클래스·속성 이름·종류·값을 비교하고 인코딩용 숫자 feature ID는 비교 정체성으로 쓰지 않는다.

## 기본값·임시 데이터

- 영속 의미 비교이므로 Ecore의 `transient/derived` 속성과 그 경로에서만 접근되는 임시 객체는 제외한다. 예: `temporaryContents`, 계산된 `ColumnGroup.member`, `GroupMembership.owner`.
- 누락 속성은 메타모델의 명시 기본값 또는 primitive/enum의 암묵 기본값과 비교한다. 미기록 `false/0/빈 목록`을 같은 의미의 명시 기록과 구분해 가짜 변경을 만들지 않는다.
- **STRING의 null/미기록과 명시 빈 문자열은 다르다.** 컬럼·도메인의 빈 자료형/기본값을 상속값으로 바꿔 비교하지 않는다.
- 도메인 값이 바뀌면 도메인의 실제 변경을 출력한다. 각 컬럼의 계산 getter 값을 중복 복제해 변경 목록을 부풀리지는 않는다. 실제 DB 영향·파급 범위는 별도 분석 과제다.
- 컨테이너 압축·ZIP 날짜·CRC·원시 객체 번호·패키지 메타데이터 URI는 이 의미 비교의 대상이 아니다. 파일 bytes 보존 검사는 별도다.

## 원본 근거와 회귀 기준

- 소유·참조·transient/derived·기본값 근거: `.analysis/ref/3.3.56/com.tomato.exerd.model_3.3.56.20260820-1610/model/exerd.ecore` 및 DB별 Ecore.
- 멤버십 key: `Column.memberships → MembershipEntry.key/value → GroupMembership.group`.
- 관계 key: `RelationManager.relation → RelationEntry.key/value → ForeignKeyColumnGroup`.
- 이 두 EMap 구조를 배열 URI만으로 연결하면 관계 하나를 삭제했을 때 뒤 항목 모두가 바뀐 것처럼 보일 수 있다. 이번 구현은 참조 key로 안정화한다.
- 기존 원본 oracle의 구조 조작 비교는 **FK 삭제: 객체 9개 삭제 + 부모 참조 3개 변경, 나머지 0건**을 기준으로 한다.

## 남은 범위

- 부분 병합·rename 승인·DB 차이·변경 SQL·의존 순서 검증은 아직 이 모듈에 없다.
- 임시 매칭을 자동 병합 근거로 사용하지 않는다. 특히 UUID가 다른 이름 충돌·익명 반복 값은 검토가 필요하다.
- 출력의 스냅샷을 원본 그래프에 그대로 splice하면 인덱스·참조·XML/바이너리 동기화가 깨질 수 있다. 후속 병합은 문서 엔진의 명시적 트랜잭션·참조 검증·두 표현 저장으로 구현해야 한다.
- 이 결과는 보존된 모델 의미의 차이다. 원본 GUI의 모든 비교 전략·DB별 getter 계산·DDL 변경 안전성을 완전히 복제했다고 보고하지 않는다.
