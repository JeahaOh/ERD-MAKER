# 로컬 복구본

- 구현: `app/src/renderer/browser/recovery.ts`, `components/RecoveryDialog.tsx`, `App.tsx`.
- 복구본은 현재 브라우저의 해당 origin 또는 Electron 앱 저장소의 IndexedDB에만 저장한다. 서버에 전송하지 않는다. 파일 저장과 별도다.
- IndexedDB 버전 2의 `recovery` 저장소를 사용한다. 기존 버전 1의 `current` 키·모델 바이트·파일명은 삭제하거나 변환하지 않고 목록에서 읽는다.

## 저장과 충돌 처리

1. 새 모델 생성·파일 열기·카탈로그 가져오기가 성공하면 새 복구 ID를 배정한다. 실패하면 현재 ID와 모델을 유지한다.
2. 각 탭·각 모델은 서로 다른 ID를 사용한다. 다른 탭의 마지막 복구본을 공통 `current` 키로 덮어쓰지 않는다.
3. Worker가 성공적으로 직렬화한 전체 `.exerd` 바이트를 응답 순서대로 저장한다. 같은 모델의 후속 변경은 해당 슬롯을 갱신한다.
4. IndexedDB 트랜잭션 완료 후에만 `로컬 복구본 저장됨`을 표시한다. 최신 응답의 저장이 실패하면 성공 상태를 표시하지 않고 파일 저장을 안내한다.
5. 복구본을 열어 작업하면 새 ID로 분기한다. 선택한 이전 복구본은 그대로 남는다.

복구 목록은 저장 시간의 역순이며 파일명·시간·크기를 표시한다. 선택한 복구본 삭제에는 해당 행의 `삭제`와 `삭제 확인` 두 동작이 필요하다. 현재 탭의 활성 복구본 삭제는 비활성화한다. 오래된 복구본을 자동 삭제하지 않으므로 저장 용량이 부족하면 사용자가 불필요한 항목을 삭제해야 한다. 다른 탭에서 명시적으로 삭제한 항목은 현재 탭의 다음 편집 시 다시 생성될 수 있다.

## 검증

`app/tests/e2e/recovery-workspace.spec.ts`에서 실제 Chromium IndexedDB를 사용해 확인했다.

- 같은 브라우저의 두 탭에서 만든 모델 각각의 복구본 보존.
- 복구 후 편집과 원래 복구본의 독립성. 원래 복구본을 다른 탭에서 다시 열고 실제 `.exerd` 다운로드를 해석해 확인.
- 삭제 확인 전 목록 유지, 확인 후 해당 항목만 삭제.
- 저장소 열기 실패를 주입한 경우 실패 안내·성공 상태 미표시·정상 `.exerd` 파일 내보내기.
- 버전 1의 단일 복구본을 버전 2에서 복구한 뒤 파일명·XML·바이너리 바이트 보존.

## 남은 범위

- 속성 입력 중 포커스를 떠나기 전의 미확정 입력은 아직 복구본에 반영하지 않는다.
- 브라우저 데이터 삭제·기기 분실·시크릿 모드 종료·브라우저의 저장소 회수는 복구본을 제거할 수 있다. 장기 보관에는 파일 저장을 사용한다.
- 저장 용량 고갈 시 마지막 정상 IndexedDB 트랜잭션의 보존 원칙은 적용되지만, 실제 디스크 부족·프로세스 강제 종료·대형 모델 장시간 반복 시험은 남아 있다.
- 복구본을 사용한 자동 Worker 재시작, 다중 창의 같은 복구 ID에 대한 잠금·삭제 동기화는 구현하지 않았다. 정상 UI의 복구는 항상 별도 ID로 분기한다.
