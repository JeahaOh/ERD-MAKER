# ERD Maker 사용 방법

기준일: 2026-10-21. 같은 편집기를 브라우저와 Electron 데스크톱 앱에서 실행한다. 회사에서 최신 기능을 확인할 때는 아래 소스 실행을 기준으로 한다. 기존 `release/` 패키지는 FK·용어사전 구현 이전 빌드이므로 최신 기능의 검증 대상으로 사용하지 않는다.

## 1. 내려받기와 실행

필수: Git, Node.js 24, npm. 저장소에 접근할 수 있는 SSH 계정을 사용한다. 원본 eXERD·Eclipse·Java·라이선스 키는 앱 실행에 필요 없다.

```sh
git clone git@github.com:JeahaOh/ERD-MAKER.git
cd ERD-MAKER
node --version
npm ci
npm run desktop
```

`npm run desktop`은 웹 화면을 빌드한 뒤 Electron을 실행한다. 브라우저로 실행하려면 다음 명령 후 `http://127.0.0.1:5173`을 연다.

```sh
npm run dev
```

인터넷이 막힌 회사 PC에서는 승인된 npm 미러나 사전에 준비한 의존성이 필요하다. 최초 `npm ci`·Electron 바이너리 설치는 외부 다운로드가 있을 수 있다. 설치 뒤 모델 편집에 API·로그인·라이선스 인증은 없다. [네트워크 확인 범위](network-and-privacy.md).

## 2. 모델 만들기·열기·저장

1. 시작 화면의 **새 모델** 또는 왼쪽 새 모델 아이콘을 누른다.
2. 모델명과 데이터베이스를 지정한다. Oracle 테스트는 **Oracle**을 선택한다. PostgreSQL 파일의 DB 선택만 Oracle로 바꿔 변환하는 기능은 지원하지 않는다.
3. 기존 파일은 상단 **열기**에서 `.exerd`를 선택하거나 파일을 화면에 놓는다.
4. 왼쪽 테이블 목록에서 선택하고 오른쪽 속성을 수정한다. 단일 속성은 Enter 또는 포커스 이동으로 반영된다. 적용 버튼이 있는 폼은 해당 버튼을 누른다.
5. 상단 **파일 저장**으로 `.exerd`를 내보낸다. 브라우저 다운로드 설정에 따라 같은 이름에 숫자가 붙을 수 있으므로 실제 저장 위치를 확인한다.
6. 저장한 파일을 다시 열어 편집값을 확인한다. 로컬 복구본은 명시적으로 저장한 파일과 별개다.

단축키: Windows/Linux는 Ctrl, macOS는 Cmd 기준으로 S 저장, Z 실행 취소, Shift+Z/Y 다시 실행, K 테이블 검색. 용어사전 창에서는 사전 자체 저장·실행 취소가 적용된다.

## 3. 테이블·관계·FK 옵션

- 테이블을 선택하면 이름·컬럼·자료형·기본값·NULL·키를 편집한다. 스키마는 탐색기의 **스키마** 탭에서 선택한다.
- 관계선을 클릭하거나 키보드 Tab으로 이동한 뒤 Enter/Space로 선택한다. Escape로 선택을 해제한다.
- 관계 속성에서 부모 키, 자식 컬럼 대응, 식별 여부, 카디널리티(관계의 개수·선택성)를 편집한다.
- **외래키 물리 옵션 → FK 옵션 적용**에서 삭제·갱신 규칙과 DB별 지연·검증 상태를 지정한다. 미지정과 명시값은 다르다.
- 식별 관계를 해제해도 기존 자식 PK는 자동 제거하지 않는다. 카디널리티 표시를 바꿨다고 UNIQUE·NOT NULL을 자동 변경하지 않는다.
- Oracle은 FK ON UPDATE 규칙을 제공하지 않는다. SET NULL은 자식 컬럼이 NULL을 허용해야 한다. 충돌하는 PK·NOT NULL은 앱이 자동 해제하지 않는다.

## 4. 용어사전

1. 왼쪽 **책 아이콘(용어사전)**을 연다.
2. 용어·물리명·설명·동의어·태그를 편집하거나 `.xdic`/`.xlsx`/`.csv`를 가져온다.
3. 이름 정책의 대소문자·구분자·접두사·길이를 설정하고 미리보기를 확인한다.
4. 충돌·미등록 용어를 해결한 다음 선택 항목에 적용한다. 모델의 일괄 이름 변경은 한 번에 실행 취소할 수 있다.
5. 사전은 `.xdic`로 별도 저장한다. CSV는 태그 설명·구분자·미해석 XML을 모두 보존하는 보관 형식이 아니다.

앱 전용 구분자 정책은 원본 eXERD에서 재저장하면 제거된다. 어휘·태그 보존과 구분한다. 사전 파일과 모델 파일은 각각 보관한다.

## 5. SQL 내보내기와 DB 테스트

1. **SQL**을 누르고 DB와 경고·미지원 목록을 확인한다.
2. **SQL 파일 저장**으로 내보내고 DB 도구에서 내용을 검토한다.
3. 생성된 SQL을 실행하는 주체는 사용자 또는 별도 검증 도구다. 앱이 회사 DB에 자동 접속하거나 SQL을 실행하지 않는다.
4. Oracle의 스키마는 기존 DB 사용자에 대응한다. `default_schema`를 그대로 회사 DB에 실행하지 말고 실제 테스트 스키마명으로 모델을 설정한다. 따옴표로 인용된 사용자 이름은 대소문자를 구분한다.

[Oracle 19c 회사 테스트](../testing/oracle19.md)에는 준비된 SQL, 기대 결과, 실패 보고 양식이 있다. [AI 테스트 지침](../testing/ai-testing.md)은 회사 AI 개발 도구에 전달할 수 있는 프롬프트다. 제품에 AI API를 연결하는 기능은 아니다.

## 6. 현재 제한

- 전체 제품은 개발 중이다. [완성도 평가](../readiness.md)는 약 60%의 개발 범위 추정이며 원본과의 동등률이나 출시 승인 점수가 아니다.
- 직접 DB 접속/카탈로그 가져오기는 PostgreSQL의 파일 기반 경로부터 구현했다. Oracle/MySQL/MariaDB의 실시간 역공학, 선택 병합·마이그레이션 SQL은 추가 개발 대상이다.
- ERwin 교환·확장 스크립트·고급 인쇄·관계선 수동 경로·모든 OS 설치·서명/업데이트는 완료되지 않았다.
- `REF/`, `.analysis/`, 이전 설치 파일은 Git에 포함하지 않는다. 회사 clone에서 원본 의존 테스트가 건너뛰어지는 것은 실제 원본 호환 검증 성공과 다르다.
